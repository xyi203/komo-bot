## 1. 定位

> 代码：`apps/client`，入口 `src/routes/_app.tsx`；Gateway 同源托管，见 `docs/clients.md` §6.1、§6.2。

TUI 与聊天渠道之外的第三个入口，给电脑上的长会话用，之后扩展到 macOS 与手机（`docs/clients.md`）。它是 Gateway 的 HTTP 客户端，不持有状态：会话正文是事件流的 fold，刷新即重建。

运行：生产里网页由 Gateway 同源托管（`komo web` 配对换 cookie 后打开 Gateway 的地址），所以浏览器里换 Gateway 就是换地址，界面里没有"改连接"。开发：`KOMO_HOME=<数据目录> pnpm --filter @komo/client dev`，`apps/client/vite-gateway-proxy.ts` 把 `/v1/*`、`/healthz` 转给本机 Gateway 并在服务端带令牌（每次请求现读 `runtime/gateway.json`），不需要配对。界面文案走 Paraglide（中文 / 英文），语言偏好只存在本机（`docs/clients.md` D9）。

## 3. 图标栏、对话列与路由

**图标栏**（64 宽，浅灰底）从上到下：Komo 标志、对话、搜索、目标、记忆，底部设置。
- 对话：回到对话页（`/`）；`GET /v1/chats` 的 `waitingCount` 大于 0 时图标上带一个黄底数字（15 秒取一次，有对话在跑时 4 秒；打开着的会话有 Run / 用户消息 / 投进来的话事件时立即重取）。
- 搜索：打开 ⌘K 弹窗（见下）。
- 目标：现在链到 `/matters`（3b 才改成 `/goals`）；记忆链到 `/memory`。当前所在的图标带灰底。
- 设置：打开设置弹窗；Gateway 连不上（红点）或事件流重连中（黄点）时图标上带一个点，悬停写出原因（判断在 `src/lib/connection.ts`，对话页的提示共用：健康检查或 `GET /v1/chats` 失败算连不上；`/healthz` 失败后每 5 秒探一次，连上后点自己消失）。旧侧栏底部的版本号与连接行没有了。
- 没有「待处理」「正在做的事」「定时」入口（P2）；`/cron` 页还在，只是没有入口（3b 删）。
- macOS 桌面壳里标志往下挪，让出左上角的红绿灯。

**对话列**（264 宽，只在对话页出现）：
- 顶上"对话"和一个加号（新支线，见下）。主对话固定在最上，标题写"主对话"；下面"支线对话"，在等你的在前、再按最后一句话的时间倒序（顺序就是 `GET /v1/chats` 给的）。没有支线时一句说明和"新支线对话"按钮。
- 一行：标题（支线没起名的写"新会话"）、最后一句话（用户或 Komo 说的，投进来的也算；没有写"还没有消息"）、时间（今天写钟点，更早写月日）。在等你的行尾一个黄圈，在跑的一个橙色呼吸点。当前所在的对话带灰底。
- 加载是三条灰条；`GET /v1/chats` 一次都没取到时写原因与重试，已有数据时失败不替换列表（连接问题由对话页上的提示与设置图标上的点说）。归档的、`chat:` 来源的存量渠道会话不在列表里（服务端过滤）。
- 支线的行悬停（或键盘聚焦、菜单开着）时「…」盖在时间的位置，菜单有**改名**与**归档**（`features/chats/chat-menu.tsx`；主对话没有）。改名是一个小弹窗（`POST /v1/sessions/{id}/name`，名字不能为空）；归档先确认（`POST /v1/sessions/{id}/delete`，带 `now: true`，是软删除，内容还在，还在跑的 Run 会被取消），归档的是当前打开的这段就回到 `/`。两个动作失败时错误写在弹窗里、不关。支线对话页右上角放同一个菜单（主对话、已归档的没有）。

**路由**：
- `/`：主对话（`GET /v1/home-session` 取会话 id，渲染对话页，顶上名字写"Komo"）。
- `/chats/$id`：支线对话，顶上名字是它的标题。派出去的任务会话也能用这个地址打开（对话列里不列它们）。
- `/chats/new`：新支线，还没有会话。发第一句话时才 `POST /v1/sessions` 建会话、再提交这句话，然后换到 `/chats/$id`（`replace`）；标题由服务端从第一句话取。建会话或提交失败时留在原地，气泡标红给重试，同一请求键，重试不会建出两个会话。输入框的草稿用固定的键 `new`。对话列里"支线对话"下临时多一行"新对话"带灰底。
- `/sessions/$sessionId`：保留成跳转，存量链接与记忆 / 事项 / 定时页里的会话链接还能进：是主会话就跳 `/`，否则跳 `/chats/$id`。
- `/matters[/$id]`、`/memory[/$id]`、`/cron[/$id]`、`/settings[/$section]`（设置只当入口，见 §15）。`/inbox`、`/inbox/$id` 已删（§14）。

搜索（⌘K，再按一次关）是浮在当前页上的弹窗（`features/palette/palette.tsx`，原型 `#palette`）：一个输入框加结果，没有类型标签排与快捷键说明行；上下键选、回车或点击进入，Esc 关。没输入时列"最近"的 8 段对话（`GET /v1/chats` 的前 8 条：标题、最后一句话、时间；主对话写"主对话"）。输入后分两组：**对话**走 `GET /v1/session-search`（标题与正文，停 200 ms 再发，最多 8 个会话，行里是命中的最近一个片段与时间，`useSessionSearch`），**目标**用 `GET /v1/matters?all=1` 的清单在前端按标题过滤（含领域与已结案的，行里是下一步或标准）；某组没有命中就不出现，都没有写"没有找到「…」"。进入：主对话到 `/`，其他对话（包括任务会话）到 `/chats/$id`，目标到 `/matters/$id`。记忆不进搜索结果（待定，`docs/redesign.md` §1.3）。

会话列表（`GET /v1/sessions?all=1&limit=50`，只取第一页，`useSessions`）还在，但不再画成侧栏：事项 / 记忆 / 定时页按 ID 找会话标题、对话页找任务会话与会话状态用的是这份。已归档的会话只能看，输入框禁用并说明原因。


## 4. 对话

> 新版：`apps/client/src/features/conversation/`（`model.ts` 事件 fold、`process.ts` 过程分组、`turn.tsx` 一轮、`tools.tsx` 回复下的悬停工具、`recall.tsx` 带上的记忆、`steps.tsx` 过程行、`thread.tsx` 正文与「正在输入」、`reply.tsx` 投进来的话与答复按钮）、`features/process/process-panel.tsx`（过程面板）、`features/trace/`（轨迹）、`features/changes/`（改动卡片与对比）；数据 hook 在 `packages/api/src/queries.ts` 的 `useSessionEvents`、`useSessionChanges`；对话页 `features/session/session-page.tsx`。

**对话页**：顶上居中一个圆形头像（Komo 标志）与下面的名字（主对话"Komo"，支线是它的标题），浮在正文上面、不占高度，正文顶上留出位置并叠一段白到透明的渐隐；没有顶栏，也就没有标题编辑、对话 / 轨迹切换、改动按钮、分叉、右栏开关。桌面壳里内置浏览器的开关是右上角的一个小图标按钮。正文只有话：用户的话与 Komo 的回复，过程不在正文里。

**回复下的悬停工具**（2b-2，P1，`tools.tsx`）：每条 Komo 回复（一轮的最终回答、投进对话的话）下面一行小工具，平时隐藏，悬停或键盘聚焦这条回复时出现（没有悬停的设备一直显示），最后一条回复常显（对话里有 Run 在跑时它也收起，免得和"正在输入"挤在一起）：
- 复制（图标按钮，复制回复正文）。
- 「看过程」：打开右侧的过程面板（见下）并定位到这一轮。一轮没有过程（只有一句回复，没有思考、调用、召回，也没有改动）时不显示；投进对话的话没有这一项。
- 「用上了 N 条记忆」：N 是这一轮最近一次 `memory.injected` 带上的条数，N = 0 不显示；点它在这一行下面展开那几条（约定实心点、参考空心圈，内容取自记忆索引），再点收起。过程面板的"步骤"里也有一行同样的召回。
- 用户的话仍是靠右的灰色气泡，下面时间与复制。
- 失败 / 取消在该轮回复的位置写一句（"本轮运行失败：原因" / "任务已停止"），不会整块消失；`context.compacted` 是轮之间的一行说明，只有 `outcome: compacted`（真换成了摘要）才画，`decayed` 与 `skipped` 不画。
- 流式：`assistant_delta` 拼到这一轮的回答位置，`message.assistant` 到了再替换成正式回复。
- 这一轮写了文件时，回复下面仍有一张改动卡片（只改一个文件写"已编辑 文件名 +a −d"，多个先列 4 行，见下"改动"），点一行打开过程面板的"改动"标签并展开这个文件。

**「正在输入」**（2b-2，`thread.tsx` 的 `Typing`）：这段对话有 Run 在跑（`view.runs` 非空，含停住等答复的）时，消息末尾是三个呼吸的点，旁边一个小的停止按钮，取消当前的 Run（`use-send.ts` 的 `stop`，`POST /v1/runs/{id}/cancel`，有几条跑着取消几条）。它取代了原来的轮次抬头（"已完成，用时 …"）和对话里展开的过程组。

**过程面板**（2b-2，P5，`features/process/process-panel.tsx`，原型 `.proc`）：从回复的「看过程」打开，在对话右侧滑出，宽 380；打开时主区让出位置（`chat-layout.tsx` 的网格多一列），窗口 ≤ 1180 时浮在对话上面。状态（开不开、看哪一轮、哪个标签、改动页展开了哪些文件、轨迹的选中与筛选）都在 `session-page.tsx` 这一层，换对话整页重挂就清掉。
- 标题栏：「过程」、上一轮 / 下一轮与"第 N 轮 / 共 M 轮"（只有一轮时不显示切换）、关闭。没有 Esc 关闭（轨迹详情自己占着 Esc）。
- 身体：这一轮用户的话（最多三行）、"用时 … · 调用 N 次 · 用上了 N 条记忆"（跑着时带转圈），下面三个标签：
  - **步骤**：这一轮的过程，沿用原来在对话里的渲染（`process.ts` 分组、`steps.tsx` 过程行），只是组默认展开：
  - 过程组：同一轮里相邻的思考与工具调用并成一组，跨步骤不拆；回复、插话把组截断。组头是类别图标加活动摘要，悬停或展开时图标换成箭头；在面板里默认展开，限高 `min(400px, 50vh)` 自己滚。结束的组按工具类别次数降序（同数按首次出现）取前三：一类"执行了命令"，两类"已搜索代码并读取文件"（两项都以"已"开头时省掉第二个"已"），三类用"，"连，多于三类末尾加"等"，没有调用是"已完成分析"。跑着的组写当前在跑的那个调用（"正在运行命令 · 详情"），没有在跑的调用是"正在分析请求 · 最近一段思考"。类别：bash 命令、read 读文件、rg 搜索代码、write 写入、edit 修改、codemode 代码、task 子智能体，其余"调用了工具"。
  - 过程行：思考是"思考 · 预览"（最近一个首行以换行结束的段落的首行），点开是全文；调用是"运行命令 / 读取 / 搜索文件内容 / 写入 / 编辑 / 代码 · 详情"，详情按 title、description、…、command、pattern、url、file_path、path 的顺序取第一个非空字段。调用点开是一张卡：状态点、工具名、完整命令（可复制）、输出（模型看到的那份预览）、"完成 · 耗时 · 大小"，卡下"查看"跳到轨迹里这一条的详情。过程行默认 `--faint`，悬停变墨。
  - 插话（`run.absorbed` 并进来的话）与过程中的说明按出现顺序排在组之间；召回是一行摘要，点开列出那几条。
  - 这段对话派出、还在跑的任务会话，在步骤底部"后台任务"下各一行，点进去（`/sessions/$id` 跳转）；对话正文末尾那几行也还在。
  - **改动**：这一轮的文件对比（`ChangesPage` 嵌进来，只给这一轮的改动；这一轮没有改动写空状态）。
  - **轨迹**：整段对话的轨迹（`TraceView` 的 `compact` 模式：单列，token 三列收起，选中记录的详情挪到记录表上面成一块），打开时滚到这一轮的轮头。
- 步骤里一次调用点开的卡片下的"查看"，切到轨迹标签、选中这条、详情开在概述（`inspect`）。

**投进对话的话（`line.reply`）**：停住的运行的提问、定时的结果由服务端作为一条 `LineReply` 事件送来（不挂 Run，负载只有 `text`、`origin`、`task`）。`foldEvents` 把它排成一项 `reply`，画成一条普通的 Komo 消息：Markdown 正文，下面一行悬停工具，只有复制（最后一条常显，其余悬停才出），按事件顺序夹在轮之间。
- **答复按钮**：对话页取 `GET /v1/interventions`（半分钟一次，对话的事件流有 Run 事件时也重取），按服务端的归属规则（对话自己停住的就是自己；任务会话沿 `home` 往上找；定时触发等回落主对话，`features/session/interventions.ts`）挑出指向这段对话、还没答复的介入，在最后一条投进来的话下面各给一排小按钮：按它的 `verdicts` 显示，第一个是深色主按钮，文案是自然的中文（批准 / 拒绝 / 放弃 / 处理好了，重新看 / 已经做了 / 确实没做），点了 `POST /v1/interventions/{handle}/answer`，成功后弹出 Gateway 回的那句话并重取清单与对话列。"放弃"点一次先变成"确定放弃"。已答复的下次取清单就没了，按钮随之消失；取不到清单时不显示。
- **已知缺口**：事件里的那句话不带介入的句柄（`LineReply` 没有 `source` / `handle`），所以按钮是按"指向这段对话"挂在最后一句话下面，同时有几条在等时每条前面写出它的问题；若最后一句其实是别的话（比如较新的定时结果），按钮仍在它下面。要一一对应，需要服务端把 `handle` 带进 `line.reply` 的负载。

过程的渲染与分组照 DeepSeek Harness 的 Chat（`packages/client/ui-chat`，规则在它的 `conversation-nodes/README.zh.md`），按轮（一条 Run）组织：

- 回答：本轮最后一条没有工具调用的 `message.assistant`；前面带工具调用的 `message.assistant` 的文字是过程中的说明（"步骤"里显示）。
- 这段对话派出、还在跑的任务会话，在对话末尾各一行，点进去（步骤里也有，见上）。
- 间距：过程行之间 4，组头与内容 8（组内展开后限高 `min(400px, 50vh)` 自己滚）。
- **轨迹**（2b-2 起在过程面板的"轨迹"标签里，见上）：照 DeepSeek Harness 的 Trajectory（`packages/client/ui-trajectory`）。原来标题旁"对话 / 轨迹"切换，同一份事件加上树上的 `komo.system` 摊平成记录：系统（初始系统提示词、之后的更新）、用户、上下文（召回、压缩、失败）、思考、助手（只调用工具时写"（仅工具调用）"）、工具（`名字 参数 → 输出`，缩进挂在发起它的那一步下）。
  - 工具栏：时长（时间概览在每条等宽与真实起止之间切换，按真实起止时抠掉没人在跑的空隙）、轮次（全部收起 / 展开）、调用（收起每一步下面的工具行）、搜索（只列命中的，概览上没命中的变淡）。

## 17. 新版（C1）与原型的差异

C1 的原则是行为以本文为准、只搬不改、只修 bug；下面是有意的差异、搬的时候修掉的原型 bug，以及没验证到的地方。

**整体**

- 原型的"改连的 Gateway"（`/__web/connection`，经 `serve.mjs`）不搬：网页由 Gateway 同源托管，换 Gateway 就是换地址；Electron 里设置的 Gateway 一节显示按钮调用 `window.komoDesktop.connection.openSettings()`（C2 实现），浏览器里只显示当前地址与版本。
- 页面路由从 hash（`#/memory`）改成路径（`/memory`），选中的 id 在路径里；设置弹窗的入口 `/settings[/节]` 打开后换回 `/`（原型换回底下那一页，新版不记上一页）。
- 回答里的 Markdown：行内代码、粗体、链接可以互相嵌套（粗体里的代码是代码，链接文字里也一样）；除 `http(s):` 外，`mailto:` 与没有协议的路径也渲染成链接（新标签页打开，同原型），`javascript:` 之类不渲染。正文里直接写的 `http(s)://…` 也是链接（2026-11-03）：只认 ASCII，碰到空白、中文或全角标点就断开；末尾的 `.,;:!?]}` 不算，`)` 只在没配对时去掉；行内代码里的不算。原型只认 `https?:`。
- 上下文环：模型没配 `context_window` 时，环与占比显示 `—`（不再是 `<0.1%`）。
- 所有日期、时间、相对时间与数字走 `Intl`，按当前语言渲染（原型写死"M月D日"一类）；界面文字两种语言，Gateway 原样返回的 `ErrorBody.message` 与机器的名字（模型 id、路径、配置键）不翻。
- 失败原因走全局 `errorText`：按 `code` 映射译文，不认识的回落原文；校验类（设置里的 400/422）仍原样给出 Gateway 的原因。

**记忆页**

- 详情键值的标签列按内容自适应宽度（原型固定 56px，英文标签会被截）。
- 列表行里点"确认 / 恢复"失败时用 toast 说一声并选中那条（原型写在详情里）；成功不再顺带选中那条（原型会，窄屏上等于推开一层详情）。
- 检索结果回来前列表显示加载条（原型继续显示原来的档）；作用域下拉在 ≤600 占 42% 宽。
- 筛选、检索词与"记一条"是否开着存在模块里，因为 `/memory` 与 `/memory/$id` 是两条路由，切换会重挂页面。
- 图上的点是带 `aria-label` 的可聚焦按钮。
- "记一条"仍允许"事实 / 经验 + 约定"的组合，由 Gateway 拒绝（原型相同，没改）。

**事项与定时**

- 新建事项是页内状态，不进地址；在等的汇总用 `Intl.ListFormat`；一次性定时显示成本地化的"月/日 时:分"。

**设置**

- 删除失败（引用方）的原因写在确认框下，不像原型那样关掉确认框、把原因放到节顶回执。
