# Web 客户端

> 状态：新版（C1 完成，2026-11-03），代码在 `apps/client/`（TanStack Start SPA 模式），接真实 Gateway、无样例数据。W0 原型（`apps/web`、`serve.mjs`）已删除。本文是界面行为的规格：每一节标出新版代码的位置；原型有、新版有意不搬或改了的，写在 §17。与 `docs/komo_bot.md` 冲突处以设计文档为准。

## 1. 定位

> 代码：`apps/client`，入口 `src/routes/_app.tsx`；Gateway 同源托管，见 `docs/clients.md` §6.1、§6.2。

TUI 与聊天渠道之外的第三个入口，给电脑上的长会话用，之后扩展到 macOS 与手机（`docs/clients.md`）。它是 Gateway 的 HTTP 客户端，不持有状态：会话正文是事件流的 fold，刷新即重建。

运行：生产里网页由 Gateway 同源托管（`komo web` 配对换 cookie 后打开 Gateway 的地址），所以浏览器里换 Gateway 就是换地址，界面里没有"改连接"。开发：`KOMO_HOME=<数据目录> pnpm --filter @komo/client dev`，`apps/client/vite-gateway-proxy.ts` 把 `/v1/*`、`/healthz` 转给本机 Gateway 并在服务端带令牌（每次请求现读 `runtime/gateway.json`），不需要配对。界面文案走 Paraglide（中文 / 英文），语言偏好只存在本机（`docs/clients.md` D9）。

- 顶部：标志、新对话、搜索（⌘K）、待处理（有停着的 Run 时带红色数字，半分钟取一次）、事项、记忆、定时，各是一页（§11–§14）；底部用户行的齿轮打开设置弹窗（§15）。页面路由 `/{memory|matters|cron|inbox}[/{id}]`，切页时关掉会话的事件流。

- 搜索（顶部"搜索"或 ⌘K，再按一次关）是居中的弹窗：输入框、一排类型（全部 / 会话 / 事项 / 记忆 / 定时）、分组的结果、底部一行快捷键（Esc 关、← → 换类型——光标在输入框两头时才换、↑ ↓ 选、↵ 打开）。没输入时"全部"列最近更新的 8 个会话和动作"新对话"；会话 / 事项 / 定时类型列全部（事项只列没结案的）；记忆类型提示输入关键词。输入后会话按标题、事项按标题、定时按名字与提示词在本地过滤，记忆走 `GET /v1/memories?query=`（停 200 ms 再发，"全部"里取 5 条、"记忆"里取 20 条）；"全部"下每类最多 5 条。行尾是辅助信息：会话的工作目录（或"已归档""子任务"）、事项的目标 / 领域、记忆的作用域、定时的时间。打开会话就切过去，其余跳到对应页的那一条。事项与定时在弹窗打开时取一次。
- 视图菜单，选择存 `localStorage`：
  - 分组：按会话树（默认）/ 按工作目录 / 单列表。会话树里任务会话按 `home` 挂在父会话下；工作目录取 `workdir`，没有的归"默认目录"，组头的 + 在该目录新建会话（`POST /v1/sessions` 带 `workdir`）。
  - 排序：最近更新 / 最近创建。
  - 筛选：隐藏已归档 / 全部对话 / 仅显示已归档。"已归档"目前映射到 `deleted` 与 `closing`，见 §9。
  - 一句话都没发过的会话（`applied_seq == 0`）不进侧栏（主会话除外）也不进 ⌘K 的最近与搜索结果；发出第一句后随 run 事件重取列表时出现。
- 主会话始终在最上。有子任务的会话名后一个 ▸；收起时下面一行"N 个子任务 ›"（有在跑的写"N 个在跑"），展开后直接列出全部子任务。打开某个子任务时它的父会话自动展开。
- 一行只有标题（运行中带圆点），不写时间。悬停、键盘聚焦或菜单开着时行尾出"…"（触屏一直显示），点开是会话菜单：重命名 R（行内改，Enter 存、Esc 放弃、失焦也存，`POST /v1/sessions/{id}/name`）、分叉 F（`/fork`，开新会话）、归档 A（`/delete`，确认一次；主会话没有）、删除 D（永久删内容，确认一次；没归档的先 `/delete` 带 `now: true` 停掉在跑的再 `/purge`，因为 Gateway 的 purge 只认已归档的；引用检查不过的原因写在菜单里，这时会话已归档）。菜单开着时直接按字母，Esc 关。置顶、标未读、移到分组这几项 Gateway 没有对应的状态，没做。
- 分组可折叠，超过上限（会话树 12、工作目录 5、单列表 20）给"显示全部 N 个"。
- 底部：Gateway 版本与连接状态（已连接 / 事件流重连中 / 连不上）。
- 已归档的会话只能看，输入框禁用并说明原因。

## 4. 对话

> 新版：`apps/client/src/features/conversation/`（`model.ts` 事件 fold、`process.ts` 过程分组、`turn.tsx`、`steps.tsx`、`thread.tsx`）、`features/trace/`（轨迹）、`features/changes/`（改动卡片与改动页）；数据 hook 在 `packages/api/src/queries.ts` 的 `useSessionEvents`。

参照 DeepSeek Harness 的 Chat（`packages/client/ui-chat`，规则在它的 `conversation-nodes/README.zh.md`），按轮（一条 Run）组织，相当于它的"标准"展示模式：

- 用户的话：靠右的灰色气泡，下面时间与复制。
- 轮次抬头："已完成，用时 2分50秒"（跑着时"进行中，用时 …"，失败"处理失败"，取消"已停止"），下面一条细线。点它收起 / 展开这一轮的过程；**回复与插话始终可见**，收起只收思考、工具调用和召回。只有回复、没有过程的一轮抬头不给开合。结束的轮默认收起，跑着的默认展开。带上记忆时抬头右侧写"带上 2 条约定"。
- 过程组：同一轮里相邻的思考与工具调用并成一组，跨步骤不拆；回复、插话把组截断。组头是类别图标加活动摘要，悬停或展开时图标换成箭头；默认收起，展开后限高 `min(400px, 50vh)` 自己滚。结束的组按工具类别次数降序（同数按首次出现）取前三：一类"执行了命令"，两类"已搜索代码并读取文件"（两项都以"已"开头时省掉第二个"已"），三类用"，"连，多于三类末尾加"等"，没有调用是"已完成分析"。跑着的组写当前在跑的那个调用（"正在运行命令 · 详情"），没有在跑的调用是"正在分析请求 · 最近一段思考"。类别：bash 命令、read 读文件、rg 搜索代码、write 写入、edit 修改、codemode 代码、task 子智能体，其余"调用了工具"。
- 过程行：思考是"思考 · 预览"（最近一个首行以换行结束的段落的首行），点开是全文；调用是"运行命令 / 读取 / 搜索文件内容 / 写入 / 编辑 / 代码 · 详情"，详情按 title、description、…、command、pattern、url、file_path、path 的顺序取第一个非空字段。调用点开是一张卡：状态点、工具名、完整命令（可复制）、输出（模型看到的那份预览）、"完成 · 耗时 · 大小"，卡下"查看"跳到轨迹里这一条的详情。过程行默认 `--faint`，悬停变墨。
- 间距：过程行之间 4，组头与内容 8，回复与相邻过程行 12，轮次抬头上下 16。
- 回答：本轮最后一条没有工具调用的 `message.assistant`，下面复制与时间；最新一轮常显，更早的轮悬停或键盘聚焦时才出（没有悬停的设备一直显示）。回答里支持代码块、标题、列表、表格、行内代码、粗体、链接。
- 失败 / 取消写在该轮末尾；`context.compacted` 是轮之间的一行说明。
- 被并入的插话（`run.absorbed`）挪进宿主那一轮的过程里。
- 这段对话派出、还在跑的任务会话，在对话末尾各一行，点进去。
- 流式：`assistant_delta` 拼到这一轮的回答位置，`message.assistant` 到了再替换成正式回复。
- **轨迹**：照 DeepSeek Harness 的 Trajectory（`packages/client/ui-trajectory`）。标题旁"对话 / 轨迹 / 改动"切换，同一份事件加上树上的 `komo.system` 摊平成记录：系统（初始系统提示词、之后的更新）、用户、上下文（召回、压缩、失败）、思考、助手（只调用工具时写"（仅工具调用）"）、工具（`名字 参数 → 输出`，缩进挂在发起它的那一步下）。
  - 工具栏：时长（时间概览在每条等宽与真实起止之间切换，按真实起止时抠掉没人在跑的空隙）、轮次（全部收起 / 展开）、调用（收起每一步下面的工具行）、搜索（只列命中的，概览上没命中的变淡）。
  - 时间概览：输入 / 模型 / 工具三条泳道，墨色深浅区分，正在跑的那格叶绿、失败的红，轮与轮之间一条竖线。点一格选中那条记录；横向拖一段，记录表只列这段里在活动的记录，Esc、双击或"看全部"清掉。
  - 记录表：按轮分段，轮头吸顶（时间、用时，收起时写几个步骤几个工具调用），右边输入 / 输出 / 思考 token 与时间四列。
  - 详情：选中一条，右边一栏（窄屏从底下升起）。顶上是类型和"第 N 轮 · 第 M 步"，下面是标签页：工具是概述 / 参数 / 结果 / Schema（树上的工具定义）/ 计时；助手是概述 / 思考 / 预览 / 原始内容 / 用量（本次请求与会话累计）/ 计时；系统是差异 / 系统提示词 / 工具。概述把各页的开头摆在一起，段标题点了切到那一页；"层级 · 助手消息"跳到发起它的那一步。Esc 关掉。
- **改动**：照 DeepSeek Harness 的改动文件卡片与 review（`packages/client/ui-deliverables`），数据由 Gateway 记（§16），前端只读：
  - 打开会话时 `GET /v1/sessions/{id}/changes` 一次拿全；之后每轮进终态时 `GET /v1/runs/{run}/changes`（Gateway 还在收尾就等它）。
  - 一轮的最终回答下面、页脚上面一张卡：只改了一个文件写"已编辑 / 已新建 / 已删除 文件名 +a −d"；多个文件写"N 个文件已更改"和合计，先列 4 行，其余折叠。每行是展示路径（目录淡、文件名墨色）、"新建 / 删除"小标、增删数（二进制写"二进制"，没存下来的写"过大"）。点一行到"改动"标签、展开这个文件并滚到它。
  - "改动"标签（"改动 N"，N 是改过的不同文件数）：按轮列出，最近一轮在上、默认展开，较早的收起；一个文件一张卡，展开时才 `GET /v1/runs/{run}/changes/{index}` 取对比，画成带新旧行号的 unified diff（最多 5000 行），新建的文件整段是加的、不逐行铺底。二进制、过大、两份相同各一行说明；取不到（Gateway 重启过）写出来。
  - 没做：悬停浮出对比、左右对比与换行切换、语法高亮、在侧栏预览或用本机应用打开文件；产出（模型用 `present` 显式交付的文件）也还没有。

## 5. 输入框

> 新版：`features/composer/`（`composer.tsx` 输入框、模型 / effort 与用量行、上下文环，`use-send.ts` 发送 / 重试 / 停止，`use-attachments.ts` 附件）；消息里的附件在 `features/conversation/attachments.tsx`。

一行：加号（选图片或文件）、文字、发送。会话有 Run 在跑且输入为空时发送键变停止；有附件或文字时是发送。

附件（2026-11-03）：图片和文件可以粘贴（截图、从访达复制的文件）、拖进输入框，或点加号选。
- **传：** 一放进来就 `POST /v1/attachments?name=文件名` 上传，请求体是原始字节。Gateway 像聊天渠道收图片一样存进 `{workspaces_dir}/inbox/web/`（komo_bot.md §11.2）：认得出的图片（png / jpg / gif / webp）按内容哈希命名，其他文件存成 `<哈希>/<原文件名>`；单个上限 20 MB。回执里有拼进正文的那行说明（与渠道逐字相同），图片还有缩略图地址。
- **框里：** 图片是方形缩略图，文件是带名字的标签；传着的半透明，传失败的标红，悬停看原因。还在传时不让发；有传失败的要先移除，不会悄悄丢掉。
- **发：** 每个附件的说明一行，排在用户文字前面，一起作为 `text` 提交。消息结构、受理、回放都不认识附件，模型自己用 `read` 去看。
- **消息里：** 用户消息开头的这些说明行拆出来显示：收件箱里的图片从 `GET /v1/attachments/{收件箱}/{文件名}` 取缩略图（聊天渠道收的图也能看），文件是名字标签，悬停看完整路径；复制按钮只复制用户写的话。临时标题跳过这些说明行，只有附件时叫「图片」「文件 a.md」。
- **桌面壳：** 走同一个 app:// 代理，不需要额外处理。浏览器拿不到本机文件路径，所以不发路径；即使能拿到，远程 Gateway 上也没有那个文件。

停止逐个 `POST /v1/runs/{id}/cancel`；Run 在跑时输入了文字或附件则是插话（`interject: true`）。发送先显示一个淡色的待发气泡，失败标红并给重试，同一请求键重发。

输入框下：左边"7 轮 94 步 · 4.4M tok · 缓存命中 95%"（从 `message.assistant` 的用量累加），右边模型、effort（按所选模型的 `efforts`）和上下文环（上一次请求的 `input_tokens` ÷ 模型窗口，与右栏同一个数）。

## 9. Gateway 缺口

做原型时发现、正式版之前要补的：

1. （已解决，C0）没有托管静态文件的路由：Gateway 现在同源托管网页，浏览器用配对换来的 cookie 鉴权（`docs/clients.md` D5、D6）。
2. 会话列表不带运行状态：要知道哪个任务在跑，得逐个 `GET /v1/sessions/{id}` 看 `unfinished`。
3. 会话的 `updated_at` 不随最后一条消息更新，侧栏的时间与"最近更新"排序因此不准。

6. 没有"归档"状态：归档后可恢复、删除才进 purge，需要新状态与接口。
7. 事件里没有请求耗时，算不出 tok/s。
8. 分叉要会话树的条目 ID，事件流里没有，所以只能分叉整段会话，做不了"从这条回答分叉"。
9. 没有读工作区文件的接口：改动卡片与对比有了（§16），但文件本身点不开预览，也没有"产出"（DeepSeek 由模型调 `present` 显式交付）。

- **Gateway**：版本与协议、启动时间、实例、数据目录、遥测、往返时间。浏览器里显示当前 Gateway 的地址（`location.origin`）；Electron 里（`window.komoDesktop?.connection?.openSettings` 存在）多一个按钮打开壳的连接设置。不能在这里改连另一台 Gateway，见 §17。
- **渠道**：读 `GET /v1/channels`。一个渠道一张卡：名字（自定义的带"自定义插件"）、状态（在跑多久 / 退出了正在重试第几次 / 起不来 / 未启用）、可下指令的人数与主动消息发到哪；退出或起不来的原因、只出不进的提醒写在卡里。启用的渠道有"探测"（`POST /v1/channels/{id}/probe`，几秒），结果写在卡底。节头"刷新"。身份名单仍只在文件里改（`docs/komo_bot.md` §11.2）。在跑的 Gateway 没有这个接口（404）时说明要装新版，并指向 `komo channel list|probe`。

## 16. 每轮改了哪些文件（Gateway 端）

> 前端（新版）：`apps/client/src/features/changes/`。

照 DeepSeek Harness 的 `packages/deliverables/workspace-changes`，在 `crates/komo-gateway/src/service/changes/`：

- **什么时候记**：Gateway 组工具表时给每个工具包一层（`Recording`）。一条 Run 第一次执行任何工具之前，给工作目录所在的 git 工作树拍一次快照；计划里带写目标的调用（`write`、`edit`）每轮每个路径第一次改之前，快照覆盖得到就只记一笔，否则把整个文件复制一份。Run 进终态（事件 hub 上的 `run.completed` / `failed` / `cancelled`）时再拍一次、比出改动，没收尾的 `GET` 会等它。`!` 命令没有输入 Run，不记。
- **快照**：私有 index（以仓库的 index 为种子）加会话自己的临时对象目录，仓库的对象库只读挂成 alternate——仓库的 index、对象、工作树、ref 都不动，这一轮开始前就没提交的改动也不会算进来；shell 改的文件在里面。被忽略的文件、仓库外的文件、不在仓库里（或没有 git）时的全部，只认文件工具的整文件副本，那里只被 shell 改的看不到。
- **只活在进程里**：摘要、快照对象与副本在内存和 `runtime/changes/<session>/`，不进 `durable.db`、不发事件；Gateway 起来时整个目录清掉，所以重启之前的轮次没有卡片（给不出对比的卡片就不给）。它不是事实来源，没有任何东西读它回去。
- **上限**：单个文件 2 MiB（更大的标"过大"、没有行数和对比）；一份记录最多列 500 个文件（`total` 照报全数）；单条 git 命令 30 秒、输出 8 MiB。git 命令清掉 `GIT_DIR` 一类环境变量、`GIT_CONFIG_COUNT=0`、不弹凭据提示、不抢可选锁。
- **没做**：改名检测（改名显示为删一个、加一个）；任务会话也记，但子任务的改动不并进父会话那一轮。

## 17. 新版（C1）与原型的差异

C1 的原则是行为以本文为准、只搬不改、只修 bug；下面是有意的差异、搬的时候修掉的原型 bug，以及没验证到的地方。

**整体**

- 原型的"改连的 Gateway"（`/__web/connection`，经 `serve.mjs`）不搬：网页由 Gateway 同源托管，换 Gateway 就是换地址；Electron 里设置的 Gateway 一节显示按钮调用 `window.komoDesktop.connection.openSettings()`（C2 实现），浏览器里只显示当前地址与版本。
- 页面路由从 hash（`#/memory`）改成路径（`/memory`），选中的 id 在路径里；设置弹窗的入口 `/settings[/节]` 打开后换回 `/`（原型换回底下那一页，新版不记上一页）。
- 回答里的 Markdown：行内代码、粗体、链接可以互相嵌套（粗体里的代码是代码，链接文字里也一样）；除 `http(s):` 外，`mailto:` 与没有协议的路径也渲染成链接（新标签页打开，同原型），`javascript:` 之类不渲染。原型只认 `https?:`。
- 右栏"上下文"卡：模型没配 `context_window` 时，环、总占比与各项占比都显示 `—`（不再是 `<0.1%`）。
- 所有日期、时间、相对时间与数字走 `Intl`，按当前语言渲染（原型写死"M月D日"一类）；界面文字两种语言，Gateway 原样返回的 `ErrorBody.message` 与机器的名字（模型 id、路径、配置键）不翻。
- 失败原因走全局 `errorText`：按 `code` 映射译文，不认识的回落原文；校验类（设置里的 400/422）仍原样给出 Gateway 的原因。

**记忆页**

- 详情键值的标签列按内容自适应宽度（原型固定 56px，英文标签会被截）。
- 列表行里点"确认 / 恢复"失败时用 toast 说一声并选中那条（原型写在详情里）；成功不再顺带选中那条（原型会，窄屏上等于推开一层详情）。
- 检索结果回来前列表显示加载条（原型继续显示原来的档）；作用域下拉在 ≤600 占 42% 宽。
- 筛选、检索词与"记一条"是否开着存在模块里，因为 `/memory` 与 `/memory/$id` 是两条路由，切换会重挂页面。
- 图上的点是带 `aria-label` 的可聚焦按钮。
- "记一条"仍允许"事实 / 经验 + 约定"的组合，由 Gateway 拒绝（原型相同，没改）。

**事项与定时**

- 新建事项是页内状态，不进地址；在等的汇总用 `Intl.ListFormat`；一次性定时显示成本地化的"月/日 时:分"。

**设置**

- 删除失败（引用方）的原因写在确认框下，不像原型那样关掉确认框、把原因放到节顶回执。
- 提供商预设的品牌名、地址和三个对话协议名不翻；渠道显示名是平台名；"谁在用"和渠道失败原因是 Gateway 的中文原文，没有译文。
- 回执里的 `komo gateway restart` 是纯文本。
- 原型里 `edit-model` / `new-model` / `use-embed` 三个动作在界面上没有入口，没搬。
- 环境变量值从不回显、粘贴整段 `.env` 拆行等安全行为照原型。

**验证**

- 在临时 Gateway 上用浏览器真点过：记忆（改约定 / 线索、遗忘、恢复、记一条、检索与筛选、窄屏进出详情），事项（转在等、继续、改标题与截止、完成与重开回执、摘下、挂定时、搁置、放弃、新建目标与领域、显示全部），定时（现在跑一次、暂停、恢复、删除），设置（预设添加提供商、改名、改默认模型、删被引用的被拒、409 重新读取、获取可用模型的错误路径、配置开关与数字与恢复默认、环境变量粘贴拆行与写入与删除、MCP 断开与连接、渠道探测的失败路径）。
- 只走查了代码：记忆的候选 / 有争议 / 被取代 / 有证据 / 有归属状态与检索降级；事项的"不再管"、409 版本冲突、monitor 触发器、原话证据；定时的"等你处理 / 出错"；带 `auth` 登录的提供商、改记忆在用向量模型后的重启提示、MCP 重连全部进行中、重建索引成功路径、渠道在跑的状态、`komoDesktop` 按钮。
- 中英文各看过一遍（1440 与 375 宽），无横向溢出、英文不截断；截图在操作者本机的临时目录，不进仓库。

**留给之后**：定时仍只有"现在跑一次 / 暂停 / 恢复 / 删除"（新建与修改走对话或 `komo cron`，同原型）；记忆页的候选 / 有争议状态等有真实数据时再看一遍样式；右栏"连接"卡接 `GET /v1/channels` 与 `GET /v1/mcp`。
