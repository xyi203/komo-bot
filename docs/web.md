# Web 客户端（W0）

> 状态：原型（2026-10-29），代码在 `apps/web/`，接真实 Gateway、无样例数据。本文记已建成的界面、它读哪些接口，以及做的过程中发现的 Gateway 缺口。与 `docs/komo_bot.md` 冲突处以设计文档为准。

## 1. 定位

TUI 与聊天渠道之外的第三个入口，给电脑上的长会话用；手机继续用飞书（`docs/roadmap-muse.md` §4.4）。它是 Gateway 的 HTTP 客户端，不持有状态：会话正文是事件流的 fold，刷新即重建。

运行：`node apps/web/serve.mjs`，打开 `http://127.0.0.1:5178`。`serve.mjs` 同源提供静态文件并把 `/v1/*`、`/healthz` 转给 Gateway，令牌只在服务端（每次请求现读 `runtime/gateway.json`）。正式版应由 Gateway 自己托管这些静态文件，见 §9。

## 2. 布局

1440 宽：左侧栏 280，主区其余；主区 = 对话（阅读列上限 720，居中）+ 右栏 336。右栏可整体收起，收起时对话独占主区。

| 宽度 | 变化 |
|---|---|
| ≤ 1180 | 右栏变右侧抽屉，默认收起，带遮罩与关闭按钮 |
| ≤ 900 | 侧栏变左侧抽屉，从顶栏左边按钮打开 |
| ≤ 600 | 右栏抽屉全宽；输入框下只留模型、effort 与上下文环 |

## 3. 侧栏

- 顶部：标志、新对话、搜索（⌘K）、待处理（有停着的 Run 时带红色数字，半分钟取一次）、事项、记忆、定时，各是一页（§11–§14）；底部用户行的齿轮打开设置弹窗（§15）。页面路由 `#/{memory|matters|cron|inbox}[/{id}]`，切页时关掉会话的事件流。
- 会话区头：搜索（按标题过滤，搜索时不分组不嵌套）、视图菜单、新对话。
- 视图菜单，选择存 `localStorage`：
  - 分组：按会话树（默认）/ 按工作目录 / 单列表。会话树里任务会话按 `home` 挂在父会话下；工作目录取 `workdir`，没有的归"默认目录"，组头的 + 在该目录新建会话（`POST /v1/sessions` 带 `workdir`）。
  - 排序：最近更新 / 最近创建。
  - 筛选：隐藏已归档 / 全部对话 / 仅显示已归档。"已归档"目前映射到 `deleted` 与 `closing`，见 §9。
- 主会话始终在最上。有子任务的会话名后一个 ▸；收起时下面一行"N 个子任务 ›"（有在跑的写"N 个在跑"），展开后直接列出全部子任务。打开某个子任务时它的父会话自动展开。
- 分组可折叠，超过上限（会话树 12、工作目录 5、单列表 20）给"显示全部 N 个"。
- 底部：Gateway 版本与连接状态（已连接 / 事件流重连中 / 连不上）。
- 已归档的会话只能看，输入框禁用并说明原因。

## 4. 对话

参照 DeepSeek Harness 的 Web UI，按轮（一条 Run）组织：

- 用户的话：靠右的灰色气泡，下面时间与复制。
- "完成，用时 30s · 2 步 ›"：一行，下面一条细线。过程收在里面——召回的记忆（约定实心光点、线索空心光点）、过程中的说明、工具调用组（"运行了 N 次调用 · 耗时"，再展开看每次调用的输出前几行）、插话。结束的轮默认收起，跑着的轮默认展开、这一行实时写当前在执行的调用。带上记忆时这一行右侧写"带上 2 条约定"。
- 回答：本轮最后一条没有工具调用的 `message.assistant`，细线下面单独显示，下面复制与时间。回答里支持代码块、标题、列表、表格、行内代码、粗体、链接。
- 失败 / 取消写在该轮末尾；`context.compacted` 是轮之间的一行说明。
- 被并入的插话（`run.absorbed`）挪进宿主那一轮的过程里。
- 这段对话派出、还在跑的任务会话，在对话末尾各一行，点进去。
- 流式：`assistant_delta` 拼到这一轮的回答位置，`message.assistant` 到了再替换成正式回复。

## 5. 输入框

一行：加号（附件，未接）、文字、发送。会话有 Run 在跑且输入为空时发送键变停止（逐个 `POST /v1/runs/{id}/cancel`）；输入了文字则是插话（`interject: true`）。发送先显示一个淡色的待发气泡，失败标红并给重试，同一请求键重发。

输入框下：左边"7 轮 94 步 · 4.4M tok · 缓存命中 95%"（从 `message.assistant` 的用量累加），右边模型、effort（按所选模型的 `efforts`）和上下文环（上一次请求的 `input_tokens` ÷ 模型窗口，与右栏同一个数）。

## 6. 右栏

可整体收起，每张卡片也可单独折叠。

- **在做的事**：`GET /v1/matters`，目标与领域及其状态。
- **带上的记忆**：最近一次 `memory.injected` 的 `uses`，按 `application` 分约定 / 线索，带用过几次与版本。
- **上下文**（默认收起，卡片头是百分比与一条分段小条）：展开后是"20% 已用 · 101k / 500k"、按窗口比例分段的条，以及对话消息、工具结果、工具定义、记忆、Skills 清单、项目规范、系统提示、压缩摘要、空闲各一行；工具定义可再展开看每个工具。口径：合计是上一次请求实报的 `input_tokens`；各项从 `GET /v1/sessions/{id}/tree` 沿 `leafId` 取当前分支，`komo.system` 按增量叠加（分段为 `null` 即删除，工具按 `toolsAdded` / `toolsRemoved` 增减），衰减过的结果按 `context_edit` 的替换视图，压缩过只算保留的部分；按字节 / 4 估算后按合计等比校准。没有单独的"MCP 工具"一项：MCP 工具默认只在 codemode 里调，不进 schema。
- **在后台**：只列这段对话派出的任务会话，在跑的在前（转圈与已跑时长），结束的写"已结束 · 时间"。定时任务不算。
- **连接**（默认收起）：Gateway 版本、启动时间、遥测状态。

## 7. 状态

- 加载：最终布局里放平的灰条，不做微光。
- 出错：留在出问题的那一块，一句原因与重试；侧栏底部连接点变红，输入框置灰。
- 空：空会话居中一句"还没有消息"；各卡片有各自的空句子。
- 动效只做反馈：折叠、抽屉、转圈；`prefers-reduced-motion` 下全部关掉。

## 8. 视觉

沿用 `DESIGN.md` 的品牌色，按"外框不放颜色"落地：苔墨为字，鼠尾草灰为侧栏底，白为对话与右栏，叶绿 `#4f6b38` 是唯一色相，只落在"在场"（带上的记忆）与"运行中"上；主按钮近黑。字体 Noto Sans + Noto Sans SC，字号 12 / 13 / 14 / 15，数字一律等宽数位。token 都在 `apps/web/styles.css` 的 `:root`。

## 9. Gateway 缺口

做原型时发现、正式版之前要补的：

1. 没有托管静态文件的路由，现在靠 `serve.mjs` 代理并替浏览器带令牌；正式版由 Gateway 同源提供，浏览器侧鉴权（SSE 的 `EventSource` 带不了请求头）要定下来。
2. 会话列表不带运行状态：要知道哪个任务在跑，得逐个 `GET /v1/sessions/{id}` 看 `unfinished`。
3. 会话的 `updated_at` 不随最后一条消息更新，侧栏的时间与"最近更新"排序因此不准。
4. 上下文构成要前端拉整棵会话树来估；应由 Gateway 在 `prepare` 组请求时记下各段 token 数直接返回，口径与窗口保护一致。
5. 没有渠道连接状态的接口，"连接"卡片只能写 Gateway 本身（MCP 已有 `GET /v1/mcp`，2026-10-30）。
6. 没有"归档"状态：归档后可恢复、删除才进 purge，需要新状态与接口。
7. 事件里没有请求耗时，算不出 tok/s。
8. 分叉要会话树的条目 ID，事件流里没有，所以只能分叉整段会话，做不了"从这条回答分叉"。

## 10. 未做与未验证

- 附件；从某条回答分叉。
- 各页的写操作只按代码走查过，没有在真实数据上触发过（都会改真实状态）：记忆的确认、遗忘、恢复、改约定 / 线索、记一条；事项的新建与全部动词；定时的暂停 / 恢复、现在跑一次、删除；待处理的答复；设置里的重新加载配置、重建索引。模型配置的增删改、单台与全部 MCP 重连、常用设置的开关 / 选项 / 数字、环境变量的批量添加（含整段粘贴）与删除都在临时数据目录的 Gateway 上真实跑过（§15），没有动过真实的 `~/.komo`。读的路径、筛选、详情、表单的显示与校验都在真实 Gateway 上看过。
- 停止、插话、发送失败重试、流式打字效果只按代码走查过，没有用真实 Run 触发过。
- 分叉、在某个工作目录新建会话只看过界面。

## 11. 记忆页

`#/memory`（选中一条是 `#/memory/{id}`），侧栏"记忆"进入；右栏"带上的记忆"卡片底部也链过来。它回答一个问题：komo 现在把哪些关于我的事带进对话，哪些等我过目。

- **标题行**：h1"记忆"，下面一句实时算出的发现，按轻重取一条：有争议的条数 > 候选条数 > "在起作用的 N 条里 M 条还没过目" / "都确认过"。右边"记一条"。
- **攒下的记忆**（一张图）：横轴是记下的日子（跨度超过 60 天按周并），一天一格，格里一个点是一条记忆，最多四列往上堆，柱顶写当天记了几条（`+11`）。颜色是在场程度——每次都带（生效的约定，实心叶绿）、相关才带（生效的线索与未分类，空心叶绿）、暂停（候选虚线圈、有争议红圈）、不再带（遗忘、取代、归档，灰点）；点的面积按带进对话的次数（开方）。格内在起作用的排在下面、再按次数。图头四个标签是图例也是筛选：默认"在起作用"（前两档一起亮），点一档只看它，其余的点淡下去，再点回到默认。点图上的点直接选中那条（不在当前档时跳到它所在的档）。图按容器宽度画，窗口变了重画。
- **列表**：一条两行——正文全文（≤ 300 字，不截断，所以能在行上直接确认），下面是使用方式、约定的条件、作用域、非生效时的状态；右边"带上 / 用上"次数叠在一格、最近带上、动作列（未确认的是"确认"，已确认写"已确认"，遗忘的是"恢复"）。排序：在起作用的约定在前、再按带上次数；不再带的按最近变动。上面是检索框（走 `GET /v1/memories?query=` 的混合检索，带归档的，降级原因如实写在列表底部）和作用域筛选；列表底部一行写检索方式与向量索引覆盖（`GET /v1/memory-index`）。
- **详情**：宽屏常驻右侧 360，默认选中列表第一条；正文、条件，动作（确认第 N 版、改成约定 / 线索、遗忘要二次确认并说明范围；遗忘的给恢复；归档与被取代的只说明原因），一口键值井（作用域、种类、来源、版本与确认、带上 / 用上、记下的模型与提示词版本、归属、有效期），取代链，证据（每条链到原会话）。经验与事实不能改成约定（§9.2 只给偏好）。
- **记一条**：在详情位置打开表单——内容、种类、作用域、线索 / 约定（约定必填"什么时候适用"）。这里记的不带会话，按 §9.3 记成已确认。
- 所有写操作都带预期 revision 与请求键（`web:{动作}:{id}:{revision}`），失败原因写在详情里。
- ≤ 1180 详情变成推进去的一层（左上角返回，回来时列表回到原来的滚动位置）；≤ 600 光阶 2 × 2，表格变两行行，次数与时间挪到第二行。

接口：`GET /v1/memories?include_archived=true&limit=500`、`GET /v1/memories?query=…`、`GET /v1/memory-index`、`POST /v1/memories`、`POST /v1/memories/{id}/{confirm|forget|restore|classify}`。归属取自 `GET /v1/matters?all=true`，结案的事项也写得出名字，并链到事项页。

## 12. 事项页

`#/matters`。回答：我现在在做什么、在等什么、哪件超期了。发现一句按轻重：超期 > 在等（列出等什么）> "N 个目标在做、M 个领域在管" > 空。

- **列表**分组：目标（在做与在等，超期在前、再按截止日期、再按新建先后）、领域、搁置（有才出现）、已结案（最近结案的 5 件，"显示全部"）。一行：状态点（目标墨点、领域墨方块、在等琥珀圈、搁置虚线圈、结案灰点）、标题、下面一行"下一步 / 在等 / 标准"；截止日期与"超期 N 天 / 还有 N 天"（按响应里 Gateway 的 `today` 算）；为它记的记忆（光点 + 条数，与记忆页同一套）；在等、搁置、结案给小标签。目标与领域为空时各留一句怎么用。
- **详情**：字段（在等、下一步、截止 / 标准），按 `docs/goals.md` §4 的表只给当前状态允许的动作——在做：完成（主）、改下一步、转为在等、搁置，文字动作改标题或截止、挂定时任务、放弃；在等：等到了继续（主）、改在等什么、完成、搁置……；搁置：继续、完成；结案：重开；领域：改名称或标准、挂定时任务、不再管。要填字的动作在详情里展开一张小表单。下面是触发器（定时任务链到定时页，monitor 链到它的会话，未结案的可"摘下"）、为它记的记忆（链到记忆页）、时间与版本、用户原话。
- 结案 / 重开的回执就地写：归档了几条线索、恢复了几条、还挂着几个触发器没删、哪些约定还归属它（链到记忆页去改归属或遗忘）。
- 新建：目标 / 领域，标题（≤ 80 字），目标可带下一步与截止日期，领域可带标准。
- 写操作带 `kind`、预期 revision 与请求键；不带会话，按 §4 是终端那一侧，直接改、不带证据。

## 13. 定时页

`#/cron`。一个列表，点开看详情（2026-10-29 收简：去掉了"接下来七天"的时间表、新建与编辑表单）。发现一句：停在等你处理的 > 上一次出错 / 排不上下一次 > "下一次是「…」，明天 14:00" > 全暂停 / 空。

- **列表**：状态点、名称、下面人话的时间（每天 / 工作日 / 每周几 / 每月几日 / 每小时 / 每 N 分钟，读不懂的照写表达式；时区与本机不同时括注）、下一次、上一次的结果（成功 / 出错 / 等你处理 / 跳过 / 排队中，没有就"还没跑过"）。在跑的在前，再按下一次排。不选时列表独占画布。
- **详情**（点一行打开，右上角关掉）：命令 / 提示词、状态、时间，现在跑一次（主）、暂停 / 恢复；跑什么（命令用等宽块）、目录、下一次、上一次（结果、时间、那次的会话、错误）、投递、重叠；删除要二次确认。窄屏是推进去的一层。
- 新建与修改走对话或 `komo cron`。

## 14. 待处理

`#/inbox`，`GET /v1/interventions`。无人值守的 Run 停下来等人的地方：要调对外工具（`confirm`）、结果不明（`verify`）、前提没了（`blocked`）。一条：问题、种类、会话、停了多久；详情里的答案按钮照抄 Gateway 给的 `verdicts`（第一个为主按钮），"到此为止"要二次确认；答复后写 Gateway 回的那句话。空的时候说明哪三种情况会停在这里，以及没有渠道配 `home_chat` 时这里是唯一能看到这些卡的地方。

## 15. 设置

设置是弹窗，不是页：开着它，底下的会话或页面照旧，不换地址、不断事件流。尺寸固定（960 × 680，屏幕放不下时四周各留 16），换节时外框不动，只换右边的内容，长了在右边滚。左边是侧栏那块纸色上的一列分节（灰药丸标当前节，配置有提醒时"配置"旁带数字），底下一行 Gateway 状态；节标题吸顶，内容从它下面滚过；右上角关闭，点遮罩或按 Esc 也关，关掉时丢下没提交的表单与删除确认。每次打开都重读一遍。手机上铺满全屏，分节变成顶上一条横着滑的药丸。界面不显示配置文件与 `.env` 在磁盘上的路径，只说"配置""环境变量"。`#/settings[/{models|config|env|index|mcp|gateway|channels}]` 只当入口：打开对应的节，地址换回底下那一页。

- **模型**（默认节，能改）：读 `GET /v1/config/models`。provider 一张卡：名字、协议、凭证状态（`env_key` 已设置 / 缺、`auth` 登录）、Base URL，卡里列出挂在它上面的模型（显示名、alias、上游 id、窗口、默认 effort，默认模型带标签）。卡上编辑 / 删除，模型行上编辑 / 删除，卡底"添加模型"，最下面"添加 provider"；右上角下拉框直接改默认模型。provider 表单：名字（新建时）、协议（Responses / Chat Completions / Anthropic Messages）、Base URL、API key（密码框，已设置时"留空不改"），"更多设置"里是凭证变量名与请求时限；`auth` 登录的 provider 不给 key 框。模型表单：alias（新建时）、显示名、provider、上游 id、窗口、默认 effort、可选档位。没挂 provider 的独立模型单列一张卡，只读。向量模型（`embeddings`）单列一张卡：每行是上游 id、alias、协议（Ollama / OpenAI 兼容）、挂的 provider 或端点、维数、凭证状态，记忆在用的带标签；行上"让记忆用它"（改 `memory.embedding`）、编辑、删除（记忆在用的由 Gateway 拒绝），卡底"添加向量模型"。表单：alias（新建时）、上游 id、协议、Base URL、API key（密码框），"更多设置"里是挂到 provider、凭证变量名、维数。改的是记忆在用的那个、或换了记忆用哪个时，回执里明说要重启 Gateway 才换上（`komo gateway restart`），重启后自动补建索引，并提醒相关度门槛按旧模型校准。配置一节也多一项"记忆用的向量模型"（下拉，头一项"不设（只按关键词检索）"）。每次写都带读到的 `version`；409（文件被别处改过）给"重新读取"，422 / 400 的原因写在表单下；成功写一句回执（变了几个键、哪些要重启），并刷新输入框下的模型菜单。删除先二次确认，还被引用的由 Gateway 拒绝并说出引用方。
- **配置**（能改）：读 `GET /v1/config/settings`。一项一张卡，左边名字和一句说明，右边控件：默认助手（下拉）、记忆（开关）、记忆用的模型（下拉，头一项"跟默认模型（…）"）、记忆检索方式（下拉，头一项"默认（…）"）、自动压缩（开关）、工具结果给模型的上限 / 工具调用时限 / 对外操作等确认（数字框 + 单位 + 保存，没写时占位符是生效值）。开关与下拉一改就写；写过值的开关与数字项在说明后给"恢复默认"（删掉那一行）。失败原因写在那一项的卡片里。最上面一张是配置检查：通过或几条提醒、生效配置的装载时间（文件之后改过标"还没装上"，不说是哪个文件）、重新加载、重新检查。
- **环境变量**（能改）：读 `GET /v1/config/env`。一张列表：变量名、已设置 / 是空的 / 缺、谁在用（"provider magpie 在用"），行尾"改值"（配置引用却不在文件里的叫"设置"）与删除（垃圾桶，二次确认，还在用的由 Gateway 拒绝并说出引用方）。值只能写入，任何地方都不显示。"添加变量"展开一叠"名字 / 值"对（值是密码框），每对右上角删掉这一对，"+ 添加"再加一对；把整段 `.env` 粘进名字框会按行拆开（跳过 `#` 行、去掉 `export` 与值两边的引号）。底部取消 / 保存，一次 `PUT /v1/config/env` 写完。
- **记忆索引**：向量模型、端点、状态与覆盖；重建。
- **MCP**：读 `GET /v1/mcp`（不等握手、不重连）。一张服务器表：服务器名、方式（本机进程 / 远程，走 OAuth 的带标签）、工具数（没连上写"—"）、状态（已连上 / 连接中 / 要登录 / 连不上），右上角"重连全部"。点一行进详情：名字、状态与工具数、方式、工具默认怎么给模型、服务器说明，"重连"只重连这一台；要登录的写出 `komo auth mcp login <名字>`，连不上的写出原因。下面列工具：原名、一行说明，和服务器默认不同的给法（直接给模型 / 不挂）、对外、只读各一个标签。"← 全部服务器"回表；换节时回到表。增删改服务器仍在配置文件里。
- **Gateway**：版本与协议、启动时间、实例、数据目录、遥测。
- **渠道**：没有接口，指向 `komo channel list|probe`；身份名单仍只在文件里（`docs/komo_bot.md` §11.2）。
